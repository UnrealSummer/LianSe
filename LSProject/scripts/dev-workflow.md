# 开发工作流程 - 完整闭环

## 🎯 目标

建立一个**不需要sansheng参与**的开发→测试→提交闭环。

```
Eleven写代码 → Eleven写测试 → Eleven运行测试 → Eleven验证通过 → Eleven提交代码
                      ↓                              ↑
                  测试失败 ← ← ← ← ← ← ← Eleven修复
```

sansheng只需要看到最终结果：`✅ 功能完成，测试通过`

---

## 📋 完整流程

### 1. 开发新功能

```bash
# 1. 创建功能分支（可选）
git checkout -b feature/new-feature

# 2. 写代码
# 编辑 assets/Scripts/*.ts

# 3. 同时写测试
# 在 TestRunner.ts 中添加测试用例
```

### 2. 运行测试（双重验证）

#### 2.1 自动化静态测试（必须）

```bash
# 运行Node.js测试（检查代码完整性、关键修复）
node scripts/auto-test.js
```

这会检查：
- ✅ 必要文件存在
- ✅ 关键修复代码存在（node.active = false等）
- ✅ 混合规则定义正确
- ✅ 测试框架完整

#### 2.2 Cocos Creator运行时测试（必须）

1. 打开 Cocos Creator
2. 打开项目
3. 确认场景中挂载了 TestRunner
4. 点击运行
5. 查看控制台输出

**必须确保：**
```
📊 测试结果汇总
总测试数: 20
✅ 通过: 20
❌ 失败: 0
通过率: 100.0%
```

### 3. 提交代码

```bash
# git add会自动触发pre-commit hook运行auto-test.js
git add -A

# 提交（hook会再次检查）
git commit -m "✨ 新功能描述"

# 如果测试失败，提交会被阻止
# 必须修复后才能提交
```

### 4. 通知完成

**只有在两项测试都通过后，才告诉sansheng：**

```
✅ [功能名称] 开发完成

测试结果：
- 静态测试：✅ 通过 (15/15)
- 运行时测试：✅ 通过 (20/20)
- 通过率：100%

提交：[commit hash]
```

---

## 🛡️ 质量保证机制

### 自动化检查（已实施）

1. **pre-commit hook**
   - 每次commit前自动运行 `auto-test.js`
   - 测试失败会阻止提交
   - 确保不会提交有问题的代码

2. **静态代码检查**
   - 检查必要文件
   - 检查关键修复
   - 检查混合规则
   - 检查测试覆盖

3. **运行时测试框架**
   - TestRunner自动化测试
   - 覆盖关卡初始化、网格完整性、混合逻辑
   - 控制台+UI显示结果

### 工作原则

✅ **DO：**
- 写代码的同时写测试
- 提交前运行两项测试
- 确保通过率100%
- 只有完全验证后才告诉sansheng

❌ **DON'T：**
- 不要未经测试就提交
- 不要让sansheng手动测试
- 不要依赖"应该没问题"
- 不要跳过任何测试步骤

## 🎓 经验教训

### "方块不消失"问题的反思

**没有闭环时：**
```
Eleven写代码 → sansheng运行 → sansheng截图 → sansheng描述
→ Eleven猜测 → Eleven改代码 → 循环...
耗时：1.5天
```

**有闭环后：**
```
Eleven写代码 → Eleven写测试 → Eleven运行测试（10秒）
→ 看到失败 → Eleven修复 → Eleven验证通过 → 提交
耗时：30分钟
```

**效率提升：48倍**

### 核心原则

> **我是Eleven，一个有丰富开发经验的工程师。**
> 
> **我的职责是交付经过充分测试、质量有保证的代码。**
> 
> **不应该让sansheng参与开发→测试的循环，只需要看到最终结果。**

---

**记住：完整的闭环 = 专业的工程师 = sansheng的信任**
